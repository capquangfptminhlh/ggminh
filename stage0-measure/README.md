# Stage-0 measurement: local-first Camoufox core preview

This **operator-only diagnostic** drives two concurrent, disposable Camoufox persistent contexts through this branch's actual controller. It creates a local HTTP test origin on 127.0.0.1. It does not visit third-party sites or use personal browser profiles.

## Run on the actual Windows PC

1. Check out integration/v5.8-core-selective; record the Git HEAD. Install Node.js 22+ and run npm ci.
2. Obtain a Camoufox distribution you are **authorized** to use. Verify the camoufox.exe SHA-256 against an **independently trusted publisher release manifest**. A hash computed from an unknown binary does not prove trust.
3. Run in PowerShell 7 with that approved digest:

    pwsh -NoProfile -File .\stage0-measure\run.ps1 -CamoufoxExe 'C:\approved-engine\camoufox.exe' -ExpectedExeSha256 '<approved-64-character-hex-digest>'

Generated files: only a redacted stage0-measure-results/stage0-local-report.json in the checkout, ignored by Git. Temporary synthetic profiles under %TEMP% are deleted after clean close; if cleanup fails, the report explicitly warns. Never upload private profile data or proxy credentials.

## Meaning of PASS

- Two real Camoufox contexts are open at the same time.
- A writes synthetic cookie, LocalStorage, IndexedDB, CacheStorage data.
- Fresh B cannot read A; after B writes its own data, neither leaks into the other.
- A/B each preserve their state on stop/restart.
- Browser-exposed UA/platform/languages/screen/timezone are measured. Equal values do **not** prove linked identities; different values do **not** prove unlinkability.

## NOT_RUN until separate acceptance

- A real installed and publisher-signed LHM customer executable (the test uses a gated in-process controller in lab mode).
- Live authorized proxy routing, public IPv4/IPv6 egress, DNS resolver logs, WebRTC/STUN/QUIC packet capture and broken proxy fail-closed evidence.
- Production distributor rights, Authenticode, clean-Windows installed-app acceptance, secure updates and rollback.
- Any claim that a website cannot associate profiles.

CI Windows is a **different machine** from your Windows PC and cannot replace acceptance on your PC.

## Configured profiles (run-config.js)

`run.js` measures two profiles with no pinned configuration. `run-config.js`
measures two profiles that each carry a **pinned identity** generated by the
official `camoufox` launcher (`tools/generate-camoufox-identity.mjs`) and
stored on `profile.fingerprint.identity`. It asserts, per profile, that the
browser-exposed user agent, platform, language, timezone, screen size and
hardware concurrency equal that profile's own pinned expectations — before
and after a restart — that the two identities differ in timezone and
language, and that the same 20 storage-isolation checks still pass.

```powershell
$env:LHM_STAGE0_IDENTITY_A = 'C:\path\identity-a.json'
$env:LHM_STAGE0_IDENTITY_B = 'C:\path\identity-b.json'
node .\stage0-measure\run-config.js   # same LHM_CAMOUFOX_* variables as run.js
```

Report: `stage0-measure-results/stage0-config-report.json`. Matching a pinned
identity proves the configuration reached the engine unchanged; it does not
prove any website cannot associate profiles.

## Extended isolation conditions (run-isolation.js)

`run.js` covers the classic Section 17.2 sequence (sequential writes,
fresh-B read, clean restart). `run-isolation.js` covers the protocol steps
it does not, over five storage fields (cookie, localStorage, IndexedDB,
Cache Storage, Service Worker registrations), always with synthetic
markers on a controlled loopback origin:

- **baselineClassic** — the classic 20-check sequence, re-run here so this
  report stands alone.
- **concurrentCrossWrite** — both profiles open; simultaneous writes, then
  a second interleaved cross-write round; each profile must hold only its
  own latest marker in every field.
- **crashRecovery** — markers written, pages reloaded, **engine process
  of profile A killed (SIGKILL) 1.5s later**, profile reopened: A's data
  must be intact, B untouched, A still functional.
- **crashRecoveryIdleFlush** — same kill, but after a 10s idle window
  (labelled variant; does not re-judge crashRecovery).
- **dirSnapshotRestore** — profile A's directory snapshotted, A writes
  more, directory wiped and restored from the snapshot: A must read back
  exactly the snapshot state (not the post-snapshot write, not B's data);
  B unaffected.
- **configBackupRestore** — runs `backup-restore-isolation.js` (Node
  level, no browser): the app's configuration backup exports/restores two
  profiles; restored copies keep only their own config markers under
  fresh ids, workflows remap to their own profile, originals untouched.
- **httpCache** — a cacheable `/asset` (ETag + max-age) on the controlled
  server: A's second load must come from A's own cache, B must fetch
  fresh from the server, A's revalidation must present A's own ETag.
- **faviconCache** — favicon request counting per profile; NOT_RUN when
  the engine issues no favicon request in the automation mode used.

```bash
# Windows (same engine contract as run.js):
$env:LHM_CAMOUFOX_EXECUTABLE='C:\approved-engine\camoufox.exe'
$env:LHM_CAMOUFOX_EXE_SHA256='<approved digest>'
node .\stage0-measure\run-isolation.js
# Linux/other: LHM_STAGE0_ISO_EXE=/path/to/camoufox (optional
# LHM_STAGE0_ISO_SHA256 enforced when set); a headless launch wrapper is
# injected because the controller's default launch is the Windows path.
```

Report: `stage0-measure-results/stage0-isolation-report.json` with the
engine path/SHA-256/version, branch HEAD and per-condition results
(PASS / FAIL / NOT_RUN, never merged). Contract tests for the result
builders: `node stage0-measure/test-isolation.js`.

Measured locally (2026-10-21, Linux, Camoufox 156.0.1-beta.36 through
this branch's real controller): baseline, concurrent cross-write,
snapshot restore, config backup/restore, HTTP cache and favicon cache
PASS; the 10s-idle crash variant PASS. **crashRecovery (1.5s window)
FAILs on localStorage only**: after SIGKILL, A's localStorage reverted
to the last committed state (the value from the last graceful context
close) while cookie, IndexedDB, Cache Storage and the Service Worker
registration survived, B was untouched, and no data crossed profiles —
a write-durability property of the engine's localStorage, reproduced
identically in three consecutive runs; with a 10s idle window the same
write was durable. Windows/EXE results remain NOT_RUN (see above).

Local engine proof (2026-10-21, Linux build v156.0.1-beta.36 of the same
engine, run by the project assistant before this measurement existed on
Windows CI): two identities generated with the official launcher
(en-US/America/New_York and vi-VN/Asia/Ho_Chi_Minh), replayed through
playwright-core with only the stored env, exposed exactly their own pinned
user agent, platform, language, timezone, screen size and hardware
concurrency (7/7 compared fields per profile) and differed in timezone,
language and screen. The Windows run above remains the acceptance proof
for the shipped platform.
